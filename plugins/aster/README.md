# Aster

구본체가 CLI의 세부 버전을 잘라 표시하는 경우, CLI가 실제 보고한 모델 ID로 화면의 모델명만 보완합니다. 선택 설정이나 실제 실행 모델을 추측해서 바꾸지 않습니다.

화면에서는 `Claude`, `Codex`를 각각 하나만 선택합니다. Claude 모델은 Fable·Opus·Sonnet·Haiku 각 계열의 최신 버전을 먼저 보여주고, 다음 순서에 각 계열의 이전 버전을 배치합니다. 같은 버전의 컨텍스트 변형은 나란히 표시합니다. 두 프로바이더 모두 유효한 구독·잔여 한도·동시 부하로 계정을 자동 분배합니다. 계정 별칭은 내부에 남아 기존 대화 ID와 기록을 유지합니다. Suite에 고정된 Paseo 0.12를 사용합니다.

0.3.0부터 설정의 **AI 계정 자동 분배**에서 연결 호스트별 계정을 추가합니다. 워크스페이스를 선택하고 계정 추가를 누르면 별도 인증 폴더의 공식 CLI 로그인 터미널이 열립니다. 로그인 완료 후 등록·구독 확인·자동 분배를 처리합니다. 최초 로그인과 철회된 인증의 본인 재인증은 필요합니다. Claude의 projects는 기존 공용 기록에 연결하고 Codex 실행의 CODEX_HOME은 유지합니다.

Codex 구독·한도 조회와 인증 갱신은 공식 app-server가 처리합니다. 각 실행 프로세스에는 공식 외부 인증 모드의 메모리 토큰을 전달하며 원래 로그인 파일을 다른 계정으로 덮어쓰지 않습니다. 새 계정으로 바꾸는 시점은 세션 연결 또는 대기 중인 턴 종료 후이며 실패한 프롬프트를 재전송하지 않습니다. 동일 계정의 갱신 요청만 처리하고 계정 ID가 달라지면 거부합니다. 무료·종료·소진·확인할 수 없는 계정은 자동 선택에서 제외하며 다시 정상 구독과 한도가 확인되면 복귀합니다. Codex 점수도 창 개수와 무관하게 Claude와 같은 기준으로 계산합니다. 초기화 시각과 창 길이가 모두 없는 창이 있으면 속도를 알 수 없으므로 그 계정은 점수를 만들지 않습니다. 현재 유료 권한이 남은 해지 예약 계정은 사용합니다.

호스트 프로바이더 정리는 공식 설정 RPC로 수행합니다. Claude·Codex만 선택 가능하게 하고 계정 별칭은 숨겨 유지합니다. 다른 기본·플러그인 프로바이더는 비활성화하고 다른 가족의 사용자 정의 프로바이더 설정은 제거합니다. 정리 전 설정은 해당 호스트의 Aster 폴더에 비공개 백업하며 로그인·대화 파일은 삭제하지 않습니다.

자동 선택은 화면과 같은 Paseo 사용량 API·캐시를 재사용하며 OAuth 갱신을 직접 수행하지 않습니다. 기본 로컬 조회는 CLI 프로세스를 띄우지 않고 루프백 API로 연결합니다. 명시적으로 설정한 외부 조회 명령은 유지합니다. 구형 내장 사용량 소스가 별도 프로필을 찾지 못하는 서버에서만 `~/.paseo/aster/settings.json`의 `profileUsageFallback`을 켭니다. 이 구버전 보완 경로는 Paseo의 Claude 사용량 구현을 사용하며 기본 설정에서는 조회하지 않습니다. 같은 계정 별칭은 중복 계산하지 않습니다.

인증 전달·복구·CLI 저장 잠금·암호화는 Settings Sync가 담당합니다. Aster 0.2.1은 본체의 단일 Claude 엔진에서 계정 메타데이터만 받아 구독 상태를 판단합니다. 새 본체에서는 Aster가 인증 토큰을 읽거나 profile API를 별도로 호출하지 않습니다. 이 RPC가 없는 구버전 호스트에서만 Sync 소유의 읽기 어댑터를 사용합니다. 인증 변경 표식을 확인해 사용량 캐시를 무효화하며, 구형 앱의 인증 RPC는 같은 호스트의 Sync로 한 번 전달하는 호환 프록시를 유지합니다. 실패한 쓰기를 재전송하지 않습니다.

Windows 자격증명 지원은 Suite 본체의 기존 Claude 조회 엔진에 통합됩니다. 기본·Windows 보고서는 같은 조회 캐시를 공유하며 같은 실제 계정은 중복 계산하지 않습니다.

각 한도의 잔여량을 초기화까지 남은 시간으로 나눕니다. 예비분은 두지 않으며 한도를 다 쓴 계정만 제외합니다. 그중 가장 작은 값이 지속 가능한 사용 속도입니다. 이를 계정 용량과 동시 사용 세션 수로 보정합니다. 점수는 `min(창별 잔여 ÷ 초기화까지 남은 시간) × 용량 ÷ (동시 세션 수 + 1)`입니다. Paseo가 보고한 Max 5x/20x를 반영하며 다른 용량은 `~/.paseo/aster/settings.json`의 `capacities`로 계정별 설정할 수 있습니다.

대상 한도는 계정마다 그 계정의 사용량 응답에 있는 창입니다. 주간 창은 항상 넣고, 5시간 창은 응답에 있을 때만 넣습니다. 요금제나 정책에 따라 5시간 한도가 다시 생기면 그 계정만 자동으로 5시간 창까지 최솟값에 넣고, 없는 계정은 주간 창으로만 계산합니다. 모든 계정에 5시간·주간 창만 있고 값이 모두 정상인 예전 형식이면 점수·순위·선택·유지 결과는 5시간 한도가 있던 때와 같습니다. 예전 응답에도 있던 Opus 주간 창(`weekly_model_opus`)은 이제 모델 창으로 반영하므로, 그 창이 있으면 Opus 세션의 점수와 모델을 모르는 세션의 순서가 예전과 달라질 수 있습니다. 5시간 창이 없는 계정은 그 이유만으로 유리하거나 불리하지 않습니다. 점수가 같을 때 5시간 여유로 순서를 정하는 보조 기준은 모든 후보에 5시간 창이 있을 때만 씁니다. 세션이 쓰는 모델의 창과 Claude Code 표면의 창도 대상입니다. 창 ID는 `<기간>_model_<계열>`·`<기간>_surface_<표면>`(기간 `five_hour` 5시간, `weekly` 168시간)으로 읽습니다. 초기화 시각이 없는 새 창은 그 기간 전체로 계산합니다. 5시간 단위 모델 한도가 생겨도 같은 방식으로 반영합니다.

같은 계정의 기본·Windows 사용량이 함께 있으면 한도 창과 초기화 시각이 유효한 최신 보고서를 사용합니다. 불완전한 보고서가 정상 보고서를 가리지 않으며 최신 소진 보고서는 그대로 반영합니다. 최신 보고서에 모델·표면 창이 빠졌거나 값이 비어 있으면 창마다 값이 있는 다른 최신 보고서로 채웁니다. 다른 출처에서 확인된 소진을 가리지 않기 위한 것입니다. 점수를 매길 때도 모델·표면 창은 점수에 쓴 보고서가 아니라 6분 안 보고서 중 그 창의 값이 있는 가장 새 보고서를 따르므로, 계정 상태 화면과 같은 값을 씁니다. 더 새 보고서의 값이 100% 미만이면 일찍 초기화된 것으로 봅니다. 소진된 창의 복귀 시각은 같은 시각 보고서 중 늦은 초기화를 씁니다. 최신 보고서가 시각 없이 소진만 보이면 그 전 보고서에서 확인된 시각을 이어 쓰되, 그 사이에 여유나 지난 초기화가 보였으면 잇지 않습니다. 주간 창은 있는데 5시간 창이 없는 최신 보고서는 그 한도가 없어진 것으로 보고, 이전 보고서의 5시간 소진을 되살리지 않습니다. 인증·한도 오류로 사용량을 무효화하면 이전에 시작된 조회가 캐시를 되살리지 않습니다.

사용량 보고서는 항목마다 따로 검증합니다. 형식이 맞지 않는 보고서는 그 항목만 제외하고 경고 한 줄을 남기며, 다른 계정의 보고서는 그대로 사용합니다. 100%를 넘는 사용률은 버리지 않고 소진으로 읽습니다. 조회가 실패하면 15초 동안 같은 실패를 그대로 돌려줍니다. 한꺼번에 재개되는 대화가 순서대로 조회 실패를 다시 기다리지 않게 하기 위한 것이며, 인증·한도 변화로 무효화하면 바로 다시 조회합니다.

Claude가 5시간 한도를 없앤 뒤 사용량 응답에는 5시간 창이 아예 없습니다. 창이 없으면 그 한도가 없는 계정으로 보고 주간 창과 모델 창만으로 점수와 소진을 판정합니다. 창은 있는데 사용률 값이 비어 있으면 불완전한 응답으로 보고 0으로 채우지 않습니다. 초기화 시각이 지났거나 읽을 수 없는 창, 시각 없이 사용 중인 창도 같습니다. 주간 창이 빠진 정상 응답도 누락한 사용량을 추정하지 않습니다. 이때는 계정 자체의 창 하나 이상에 여유가 확인되고 확인된 소진이 없는 최신 계정으로 공식 Claude CLI의 인증·한도 확인을 진행합니다. 세션 모델의 창이 이렇게 불완전하면 그 모델 세션에만 같은 경로를 쓰고 다른 모델 세션은 점수로 고릅니다. 새 대화뿐 아니라 기존 소진 대화의 재개와 한도 오류 뒤 연결 전환에도 같은 후보 판정을 사용합니다. 확인된 소진·인증 거부·오래된 응답은 이 경로로 우회하지 않습니다.

5시간 창만 소진된 계정은 5시간 초기화까지, 주간 창만 소진된 계정은 주간 초기화까지 제외합니다. 둘 다 소진되면 늦게 풀리는 쪽까지입니다. 모델 창만 소진된 계정은 그 모델 세션에서만 그 창의 초기화까지 제외합니다. 계정 상태 화면, 소진 거절 메시지의 가장 빠른 초기화 시각, 자동 복귀 시각도 같은 기준입니다.

모델 한도는 사용량 응답의 `weekly_model_<계열>` 창(예: Fable·Opus)과 앞으로 생길 수 있는 `five_hour_model_<계열>` 창으로 읽습니다. 계열은 모델 ID `claude-<계열>-…`에서 정합니다. Claude Code 표면 창(`weekly_surface_code` 등)은 모든 Claude 세션의 한도로 반영합니다. Paseo는 Claude 대화를 Claude Code로 실행하기 때문입니다. 다른 표면 창은 Paseo 세션의 한도가 아니므로 분배에서 무시하고, 소진되면 상태 화면에만 표시합니다.

세션 모델은 세 경로로 확인합니다. 본체가 세션 열기 요청에 넘긴 모델을 먼저 쓰고, Aster가 직접 다시 연결할 때는 그때 고른 계열을 씁니다. 요청의 모델이 비어 있으면(`null`, 제공자 기본 모델) 본체도 실제 모델을 모르는 것이므로 다음 경로로 넘어갑니다. 둘 다 없으면 에이전트를 조회해 실행 중인 모델을, 그것도 없으면 설정의 모델을 씁니다. 턴 종료 판정과 같은 순서여서 두 판정이 서로 다른 모델로 계정을 고르지 않습니다. 에이전트 조회는 세션 모델에 따라 고를 계정이 달라질 때만 합니다. 마지막으로 확인한 모델은 메모리에 두고 대화가 닫히면 지웁니다. 조회가 2초 안에 답하지 않으면 15초 동안은 다음 조회를 기다리지 않고 마지막으로 확인한 모델로 판정합니다. 한꺼번에 재개되는 대화가 대기를 쌓지 않게 하기 위한 것입니다. 사전 점검도 요청의 모델로 판정합니다.

모델을 알 수 없으면 모델 창은 무시하고 계정 전체 한도만 봅니다. 다만 점수가 20% 안쪽으로 비슷하면 소진된 모델 창이 없는 계정을 먼저 씁니다. 기본 모델 새 대화가 Fable만 소진된 계정에 붙는 일을 줄이기 위한 것이며 예비분은 두지 않습니다. 세션 모델의 창이 100%인 계정은 그 세션 후보에서 빠집니다. 이 제외는 10분 유지·20% 우위 규칙보다 우선하며, 같은 계정의 다른 모델 세션은 그대로 둡니다.

본체가 한도로 거절된 모델 변경을 새 모델로 세션을 다시 열면 요청에 `modelChange`가 붙습니다. 이때는 10분 유지·20% 우위 없이 새 모델 한도에 여유가 가장 큰 계정으로 옮겨 엽니다. 방금 그 모델을 거절한 계정은 사용량에 아직 여유가 보여도 이 다시 열기에서 마지막 후보로 미루고, 모델 계열을 알면 한도 안내처럼 그 계열로만 점증 대기 차단을 걸어 그 계정의 같은 모델 세션과 새 대화도 피하게 합니다. 차단되지 않은 다른 후보가 없으면 차단 중인 계정까지 넣는 마지막 단계에서 다른 차단 계정과 같은 기준으로 고르고, 그 계정의 CLI가 한도를 직접 확인합니다. 거절된 모델 변경은 세션이 실제로 쓰는 모델로 기억하지 않습니다. 계정을 고르는 동안 그 세션에 턴이 시작되면 본체가 다시 열기를 취소하고 기존 세션을 그대로 두므로, Aster도 고른 계정에 바인딩하지 않고 새 모델을 기억하지 않으며 원래 계정 환경을 돌려줍니다. 거절한 계정에 건 모델 차단은 그대로 둡니다. 사용량 보고서로 모든 계정에서 그 모델 한도나 계정 전체 한도가 소진된 것이 확인되면 `Aster: 모든 Claude 계정의 Fable 한도가 소진되었습니다. 가장 빠른 초기화는 11. 17. 오후 03:00(한국시간)입니다.`처럼 거절합니다. 본체는 모델 변경을 실패로 처리하고 기존 세션을 그대로 둡니다. 사용량을 모르거나 보고서가 불완전하면 거절하지 않고 CLI 확인 경로를 포함한 기존 규칙으로 엽니다. `modelChange`를 보내지 않는 이전 본체에서는 기존 동작을 유지합니다. 모든 계정의 그 모델 한도가 소진되면 새 대화는 가장 빠른 초기화 시각과 함께 거절합니다. 기존 대화는 다른 모델로 바꿀 수 있도록 원래 계정으로 엽니다.

계정 상태 화면은 5시간 창이 있는 계정을 `자동 분배 중 · 5시간 31% · 주간 59%`, 없는 계정을 `자동 분배 중 · 주간 59%`처럼 표시합니다. 특정 모델만 소진된 계정은 `사용 가능 · 주간 59% · Fable 한도 소진 · 11. 17. 오후 03:00 이후 복귀`처럼 표시합니다. 주간 사용률을 아는 계정에는 `첫 사용 후 사용량 표시`를 표시하지 않습니다.

메뉴 모듈을 일시적으로 읽지 못하면 다음 호스트 설치나 플러그인 재로드에서 같은 lease로 다시 시도합니다. 0.1.2의 실패·정상·준비 중 lease가 남아 있으면 기존 wrapper를 복원하고 새 수명 관리로 이관합니다. 이전 owner가 남아 있는 동안 메뉴를 유지하며, 이전 설치의 늦은 응답이나 해제가 새 wrapper를 바꾸지 않습니다.

현재 계정은 10분간 유지하고 이후 다른 계정의 점수가 20% 이상 높을 때 전환합니다. 한도 소진·조회 오류로 현재 계정이 제외되면 유지 제한을 적용하지 않습니다. 초기화 시각이 지났더라도 사용량을 임의로 0으로 바꾸지 않습니다. Paseo의 5분 캐시를 존중하고 6분이 넘은 데이터는 제외합니다.

공식 Claude CLI가 한도 안내를 돌려준 계정은 안내에 적힌 초기화 시각까지 자동 선택에서 뒤로 미룹니다. 시각이 없는 안내와 한도 오류는 5분, 15분, 60분 순으로 미루며, 차단 뒤에 시작한 턴이 다시 한도에 걸릴 때만 단계를 올립니다. 차단 뒤에 시작한 턴이 그 계정에서 정상 완료되면 해제하고, 시각 없는 차단은 사용량 보고서의 창이 새로 시작돼도 해제합니다. 해제 직후 같은 한도가 다시 오면 다른 턴의 성공으로는 풀지 않고 끝까지 유지합니다. 안내가 Opus·Sonnet·Fable 같은 모델 한도를 가리키면 그 계열로 확인된 대화만 옮기고 같은 계정의 다른 모델 대화는 그대로 둡니다. `5-hour limit`·`session limit`·`weekly limit`·`usage limit … resets 3pm`처럼 모델을 밝히지 않은 안내는 계정 전체를 차단합니다. 사용량 보고서에 5시간 창이 없어도 5시간 한도 안내는 같게 처리합니다. 5시간 한도 안내의 차단은 보고서에서 5시간 창이 사라져도 안내된 시각이나 대기 단계가 끝날 때까지 유지합니다. 창이 사라진 것만으로는 그 한도가 풀렸다는 근거가 되지 않기 때문입니다. 안내가 5시간이나 주간 한도를 밝혔으면 새로 시작된 창과 조기 초기화도 그 기간의 창으로만 판단합니다. 안내에 모델 이름이 없어도 방금 조회한 사용량에서 그 대화 모델의 창만 100%이고 계정 전체 창에 여유가 있으면 그 모델 한도로 봅니다. 5시간 한도를 밝힌 안내는 모델 한도로 보지 않습니다. 모델을 아직 알 수 없는 새 대화는 그 계정을 피합니다. 차단 중 사용량 보고서가 그 한도를 소진으로 보인 뒤, 차단 이후 조회에서 100% 미만을 보이면 예정보다 일찍 초기화된 것으로 보고 안내된 시각 전이라도 해제합니다. 소진을 보인 적이 없는 사용량은 CLI 안내보다 늦을 수 있으므로 차단을 풀지 않습니다. 모델을 밝히지 않은 계정 단위 차단은 모델 창까지 모두 100% 미만이어야 풉니다.

이 차단은 순위만 낮춥니다. 고를 수 있는 계정이 차단된 계정뿐이면 새 대화·재개·사전 점검을 막지 않고 그 계정으로 열어 공식 CLI가 한도를 직접 확인합니다. 사용량 보고서로 확인된 5시간·주간·세션 모델 소진과 구독 종료는 이 경로로 우회하지 않습니다. 차단은 메모리에만 두므로 Aster나 데몬을 다시 시작하면 다음 한도 안내부터 다시 적용합니다. 포트·줄 번호·종료 코드에 섞인 숫자, 컨텍스트·예산 한도 문구, MCP 이벤트 구독 오류는 Claude·Codex 모두 계정 한도나 접근 실패로 보지 않습니다.

새 세션·재개·reload 시 자동 선택합니다. 턴 종료 후 더 적절한 계정이 있으면 대기 상태와 권한 요청을 확인한 뒤 공식 `agent reload`를 호출합니다. 실패한 요청을 자동 재전송하지 않습니다. 기존 대화도 다음 턴이 끝나면 자동 관리에 편입합니다. 동시 사용자 입력과 reload 사이의 최종 원자적 보장은 Paseo API 범위에 따릅니다.

한도 전환 뒤 작업을 이어가게 하려면 `~/.paseo/aster/settings.json`에 `"continueAfterLimitSwitch": true`를 넣습니다. 기본은 꺼져 있습니다. 켜면 한도 안내로 끝난 턴 뒤 다른 계정으로 reload가 끝났을 때만, 원래 요청과 완료된 작업을 검토하고 남은 작업만 이어서 하라는 메시지를 그 대화에 한 번 보냅니다. 원래 프롬프트를 그대로 다시 보내지는 않습니다. 사용자가 취소한 턴, 인증·구독 오류, 전환이 실패했거나 같은 계정으로 돌아온 경우, 그 사이 사용자가 새 메시지를 보냈거나 대화가 작업 중·권한 승인 대기인 경우에는 보내지 않습니다. 이어가기 메시지로 시작한 턴이 다시 한도에 걸리면 연결만 바꾸고 더 보내지 않습니다.

계정이 바뀐 세션 열기, 한도 차단과 해제, 턴 종료 뒤 전환, 한도·인증·구독 오류를 감지하고도 전환하지 않은 이유(다른 후보 없음·같은 계정·작업 중·권한 대기·새 턴 시작), 세션 열기 거절은 `[aster]` 로그에 한 줄씩 남깁니다. 정상 턴마다 기록하지는 않습니다.

설치·업데이트는 [Suite 배포 절차](../../README.md)를 사용합니다. 이 소스 하위 폴더를 독립적으로 설치하지 않습니다. 계정 레지스트리·로그인·개인 설정은 배포본에 포함하지 않습니다. 기존 대화와 계정별 공유 projects 경로는 그대로 유지합니다.

설정 파일이 없으면 설치된 Paseo의 CLI를 사용합니다. 이전 설정에 개발 프로젝트의 node_modules CLI 경로가 남아 있어도 대상 PC의 Paseo로 전환합니다. 사용자 지정 명령은 유지하며 PASEO_CLI 환경 변수로 실행 파일을 지정할 수 있습니다. 용량 조정은 기존 settings.json의 capacities를 사용합니다.

개발 PC에서만 Node.js 22.12 이상과 pnpm 12.4.1을 사용해 다음을 실행합니다. 테스트와 번들 검증은 합성 데이터와 격리된 실행을 사용하며 실제 계정이나 설치된 Paseo가 필요하지 않습니다.

```powershell
pnpm install --frozen-lockfile
pnpm test
pnpm typecheck
pnpm verify:bundle
```

`pnpm status`는 계정 ID·잔여량·초기화 날짜·선택 결과만 출력합니다. 모델 요청은 보내지 않습니다. 모든 계정을 사용할 수 없으면 새 자동 세션 시작을 명확한 오류로 중단합니다. 기존 대화의 재개·reload·가져오기는 사용량 조회나 자동 선택에 실패해도 기존 환경을 유지해 진행합니다. 이는 인증을 복구하지 않으며 메시지 전송에는 유효한 Claude 로그인이 필요합니다. 이전 로그인 표시는 현재 인증을 보장하지 않습니다. 개별 인증 오류는 Paseo의 사용량 화면에서 확인합니다.

`ASTER_DISABLED=1`을 세션 환경에 넣으면 자동 선택을 제외합니다. API 키·OAuth 토큰·클라우드 인증·커스텀 Anthropic URL을 지정한 세션에도 개입하지 않습니다. 해제 명령은 `paseo plugin disable aster --json`입니다. 기존 대화와 로그인은 유지됩니다.

Claude가 인증 갱신 오류를 반환하면 대화 기록을 유지하고 대기 중인 연결을 현재 계정 경로로 한 번 새로고침합니다. 같은 계정이 선택돼도 적용하며, 오류가 일반 응답으로 전달된 경우도 감지합니다. 사용자 요청은 자동 재전송하지 않습니다. 성공 응답 전까지 반복 복구하지 않고, 작업 중이거나 권한 승인을 기다리는 연결도 건드리지 않습니다. 재개 시 사용량 조회에 실패해도 기존 계정을 식별할 수 있으면 현재 레지스트리의 경로를 사용합니다. 실제로 인증이 철회된 경우에는 공식 재인증이 여전히 필요합니다.

계정별 provider 설정은 두 계정의 공식 사용량 조회와 기존 대화 재개를 위해 내부에 유지합니다. Aster의 클라이언트 확장이 활성 호스트의 계정별 Claude 프로필을 숨기고 새 대화 메뉴를 기본 `Claude`로 통합합니다. 설정 동기화로 프로필이 복원돼도 선택 화면은 한 항목을 유지하며 다른 호스트와 기존 대화의 모델 목록은 보존합니다. 설치 앱 파일 수정이나 관리자 권한은 필요하지 않습니다. 현재 Paseo 0.12 앱 번들에서 고유한 모듈 내보내기와 런타임 계약을 확인한 뒤 적용합니다. 호환되지 않는 앱은 메뉴를 수정하지 않고 클라이언트 로그에 원인을 남깁니다. 여러 호스트 설치는 조회와 패치를 공유하고 마지막 해제에서 복원합니다. 현재 클라이언트 확장만 사용하며 설치 앱을 수정하는 이전 메뉴 패치 도구는 이 배포본에 포함하지 않습니다.

0.1.11은 빈 레거시 프로필을 복구할 때 원래 프로필의 CLI 잠금을 설정 반영과 저장 완료까지 유지합니다. 재로드로 겹친 여러 인스턴스가 같은 계정을 각각 다른 경로로 옮기는 경합을 차단합니다. 빌린 잠금에서도 Windows 저장 저널 복구와 잠금 소유권 검사를 유지합니다. 저장이 완료된 뒤 잠금 정리만 실패하면 이미 반영된 로그인 경로를 이전 경로로 되돌리지 않고 사용량 캐시를 무효화합니다. 저장 코드의 계약 버전이 다르면 인증 쓰기를 시작하지 않습니다.

0.1.12는 Claude 개인 구독의 현재 사용 권한을 공식 OAuth profile API에서 확인합니다. 새 대화·재개·턴 종료 후 선택 시 계정마다 최대 1분에 한 번 확인하며, 같은 계정의 별칭은 조회와 제외를 공유합니다. 해지 예약만 있고 현재 유료 권한이 남아 있으면 계속 사용합니다. 실제 무료 전환·구독 종료 또는 결제 오류가 확인되면 해당 계정만 제외하고, 다른 정상 계정으로 기존 대화 연결을 전환합니다. 구독 오류가 일반 응답으로 전달돼도 처리하며, 오래된 정상 사용량이 최신 거부·무료 플랜 보고서를 덮지 못하게 합니다.

제외 상태는 기기 안에 계정 식별 해시·시각·참/거짓만 기록해 재로드 후에도 유지합니다. 재구독 후 유효한 인증으로 공식 프로필의 정상 권한이 확인되면 자동 복귀합니다. 인증이 만료·철회된 경우 기존 공식 CLI 갱신·동일 계정 인증 전달 또는 본인 재인증이 필요할 수 있습니다. 네트워크 오류만으로 기존 제외를 지우지 않으며, 로그인·대화 파일을 삭제하거나 인증을 직접 갱신하지 않습니다. 모든 계정의 구독이 종료돼도 기존 기록은 열 수 있으며 새 자동 대화에는 구독 상태 확인 오류를 표시합니다. 구독 종료를 확인하기 전 이미 진행 중인 요청의 실패까지 없앨 수는 없습니다. 실패한 요청은 재전송하지 않고, 새 사용자 턴이나 권한 승인 대기는 중단하지 않습니다.
